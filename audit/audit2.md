## 3. Новые находки

- 🟡 **Н1. gRPC API без аутентификации, при импорте конфига Xray может слушать `0.0.0.0`.**
  - В `xray_config.rs` пустой `listen` у `dokodemo-door`-входа API превращается в `0.0.0.0`, как в Xray.
  - У API нет ни токена, ни TLS, ни проверки адреса (`api.rs`, `ApiConfig::validate` проверяет только список сервисов).
  - HandlerService умеет добавлять пользователей. Значит, любой, кто достучится до порта (часто 10085), добавит себе UUID и получит бесплатный прокси, а через StatsService прочитает почты пользователей и трафик.
  - Свой пример (`127.0.0.1:10085`) безопасен. Риск — в чужих конфигах Xray/панелей, где `listen` опущен.
  - Это непоследовательно с новой проверкой открытого SOCKS.
  - Рекомендация: отклонять API на не-loopback адресе (или требовать явного флага) и хотя бы писать `warn!`.
- 🟡 **Н2. На сервере `*.internal` и другие клиентские исключения пропускают приватные ответы.**
  - Список разрешённых имён для rebinding строится из `fakeip_exclude`. Его значения по умолчанию придуманы для клиента: `local`, `lan`, `localdomain`, `home.arpa`, `internal`, `localhost`.
  - На GCP `metadata.google.internal` резолвится в `169.254.169.254`. Если в конфиге сервера нет IP-правил (например, импортированный конфиг Xray без `geoip:private → blackhole`), пользователь сервера достанет метаданные облака по имени.
  - С правилом `ip_private → block` из примеров это закрыто: имя перепроверяется по адресам.
  - Рекомендация: на сервере не брать `fakeip_exclude` в разрешённые, только `allow_private_answers`; либо добавлять `ip_private → block` при импорте конфига Xray.
- 🟢 **Н3. Лишние ~100 мс в рукопожатии REALITY.**
  - `probe` ждёт `FLIGHT_GAP = 100 мс` тишины после последней записи `dest`, и только потом сервер отвечает.
  - На проводе: свой клиент получает ServerHello через 235–261 мс, а `dest` и повтор — через 149–155 мс.
  - Пассивный наблюдатель, сравнивающий RTT TCP и задержку ServerHello, видит постоянную надбавку. Xray тоже ждёт `dest`, так что задержка на величину RTT до `dest` естественна, но надбавка в 100 мс — своя.
  - Варианты: заканчивать чтение, когда набран объём сертификата/Finished, или сократить паузу.
- 🟢 **Н4. TCP/53 и DoT к роутеру теперь уходят на сервер.**
  - Правило `port [53, 853] → proxy` стоит раньше `ip_private → direct`. Запрос к `192.168.1.1:53` по TCP уходит на сервер, а тот набирает этот адрес **в своей сети**. С `ip_private → block` из новых примеров запрос просто не пройдёт, без него попадёт в чужую LAN.
  - Утечки больше нет, но DNS по TCP к локальному резолверу сломан.
  - Аккуратнее перехватывать TCP/53 в TUN и отдавать его своему DNS-серверу, как уже делается для UDP/53.
- 🟢 **Н5. Фильтр rebinding может сломать легальные сценарии.**
  - Публичные имена с приватными адресами: `*.plex.direct`, `nip.io`/`sslip.io`, корпоративный split-horizon. Для direct они теперь блокируются.
  - В движке это настраивается через `dns.allow_private_answers`, но клиент (`plan.rs`) это поле не заполняет и в настройках его нет. Пользователь приложения не сможет добавить исключение.
- 🟢 **Н6. Окно часов 120 с выключить нельзя.**
  - Клиент с часами, отстающими больше чем на 2 минуты, молча уходит на `dest` и выглядит как «сервер не работает».
  - Для Xray-совместимых конфигов поведение отличается: у Xray 0 значит «проверки нет».
  - Это осознанный выбор (описан в `config.rs` и README), но причина видна только в debug-логе сервера. Стоит писать её на уровне info.
  - Кэш повторов живёт в памяти процесса: после перезапуска или на соседнем сервере с тем же ключом повтор внутри окна снова пройдёт. Для 120 с это приемлемо.
- 🟢 **Н7. Мелочи.**
  - Конфиг с UTF-8 BOM не читается, а сообщение непонятное: `config: expected value at line 1 column 1`. Windows PowerShell 5.1 по умолчанию пишет BOM.
  - FFI-проверка в `unbihex_stop` отказывает в вызове из **любого** потока tokio, а не только из потоков движка. Для Kotlin/Swift это не важно.
  - `cargo fmt --check` находит расхождения в изменённых файлах (`config.rs`, `dispatcher.rs`, `inbound/reality.rs`, `client.rs`). В `client.rs` константа `MIN_LAN_PASSWORD` стоит между `use`.

## 4. Приоритеты

1. Закоммитить исправления и влить в `main`. Сейчас они существуют только в рабочем дереве.
2. Н1: запретить или предупреждать про gRPC API на не-loopback адресе.
3. Н2: не брать клиентские `fakeip_exclude` в разрешённые для rebinding на сервере, или добавлять `ip_private → block` при импорте конфига Xray.
4. Н3: убрать фиксированную паузу 100 мс в `reality_shape::probe`.
5. Н4: перехватывать TCP/53 в TUN вместо отправки на сервер.
6. Остальное из первого аудита, что осталось: PSK, spiderX, шифрованный DNS для direct.
