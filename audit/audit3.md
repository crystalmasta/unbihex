## 3. Новые находки

- 🟢 **Б1. Строка предупреждения про `geoip:private` разорвана пробелами.** В `xray_config.rs` литерал перенесён на новую строку без `\`. В выводе получается «users can reach the`··············`server's own network» — 14 пробелов посреди фразы.
- 🟢 **Б2. DoT (853) к роутеру уходит на сервер.**
  - Правило `port [853] → proxy` стоит раньше `ip_private → direct`. DoT к `192.168.1.1:853` сервер набирает в своей сети: с `ip_private → block` запрос не проходит, без этого правила попадает в чужую LAN.
  - Утечки нет, а DoT к роутеру в локальной сети — редкость: Android Private DNS обращается по имени к публичным адресам.
  - Варианты: `block` вместо `proxy` для приватных адресов на 853 или оставить как есть.
- 🟢 **Б3. Остаточная задержка REALITY до 50 мс.** При RTT до `dest` от 100 мс сервер отвечает примерно на 50 мс позже, чем `dest` (раздел 2.2). Для типичной установки, где `dest` близко, надбавка мала. Убрать её полностью можно, если заканчивать чтение по содержимому, а не по паузе: ждать запись с Finished, когда её размер известен из TLS-записей.
- 🟢 **Б4. DNS по TCP в TUN без ограничения числа соединений.**
  - Каждое соединение на порт 53 запускает отдельную задачу и сразу выделяет буфер 64 КБ.
  - Лимит `max_connections` на эти задачи не распространяется, но тайм-аут простоя 10 с есть.
  - Источник — только локальные приложения за TUN, так что риск — расход памяти от сбойного или враждебного локального процесса.
- **Совместимость (не уязвимость).**
  - Конфиг Xray с явным `"listen": "0.0.0.0"` у API теперь не запускается вообще, хотя раньше работал. Это осознанный выбор, но обойти его флагом нельзя. Панели, которые обращаются к API по сети, придётся переводить на SSH-туннель или прокси с аутентификацией.
  - Окно часов 120 с выключить по-прежнему нельзя.
