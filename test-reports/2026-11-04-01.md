## Расхождения (главное)

1. **HTTPUpgrade + сервер sing-box — не работает** (VLESS/VMess/Trojan, и в конфиге, и по ссылке, и после импорта).
   sing-box отвечает `404`, в логе `real websocket request received`: наш запрос HTTPUpgrade несёт
   `Sec-WebSocket-Key` и `Sec-WebSocket-Version: 13` (`outbound/ws.rs`, `connect()`, общая шапка для WS и HU),
   а sing-box такой запрос отвергает как настоящий WebSocket.
   Эталон: **клиент Xray 26.10.31 тоже не подключается** к HU sing-box (та же ошибка); **клиент sing-box подключается
   и к HU sing-box, и к HU Xray**. Значит, sing-box и Xray как серверы ведут себя по-разному: Xray принимает оба варианта,
   sing-box только запрос без ключа. Наш клиент совместим только с Xray. Как исправить: для `httpupgrade: true` не слать
   `Sec-WebSocket-Key`/`Version` (так шлёт sing-box, и сервер Xray это принимает). Минус: шапка будет отличаться от той, что шлёт клиент Xray.
2. **Hysteria2 UDP > ~4000 B через сервер sing-box — ответ не приходит** (≤4000 B ok, 4200 B уже нет; в sing-box
   и в синк пакет доходит, теряется ответ сервера). Эталон: **у клиента Xray (hysteria v2) то же самое** (4200 и 8000 B — нет ответа).
   Сервер Xray возвращает 8000 B и нашему клиенту, и своему. Похоже на ограничение sing-box как сервера (фрагментация ответа), а не на нашу ошибку.
3. **VMess, half-close через sing-box**: после `shutdown` (завершающий блок) sing-box не передаёт EOF до назначения;
   соединение закрывает наш relay через `HALF_CLOSE_GRACE` = 10 с (замер через `unbihex-cli`: EOF через 10.0 с).
   Xray закрывает такое соединение через 1 с (свой таймер uplinkOnly), клиент Xray к sing-box тоже рвёт его через 1 с.
   Данные не теряются, но приложения, которые после half-close ждут EOF, ждут 10 с вместо 1. Низкая важность.
4. **REALITY и отпечатки** (поведение серверов, наш клиент ведёт себя так же, как клиент Xray):
   | fp | сервер Xray | сервер sing-box | клиент Xray → Xray / sing-box |
   |---|---|---|---|
   | chrome, firefox, safari | ok | ok | ok / ok |
   | ios, edge | fail (нет ML-KEM) | ok | fail / ok |
   | randomized | fail | ok | fail / **fail** |
   | none (rustls) | fail | ok | — (в Xray нет) |
   Сервер Xray (REALITY с 2026-09) требует X25519MLKEM768, sing-box 1.14.4 — нет. Наш `randomized` работает с sing-box,
   хотя у клиента Xray `randomized` не работает ни с одним сервером. Ошибка у нас понятная: `REALITY: the server did not prove the key`.
5. **Shadowsocks 2022** (`2022-blake3-*`) не поддерживается: `unsupported: shadowsocks method …`. В `list` после импорта
   сервер помечен «не поддерживается» с понятной причиной. И sing-box, и Xray его поддерживают. Это недоделанная функция, а не ошибка совместимости.
6. SOCKS5-вход отвечает на UDP ASSOCIATE `0x07`, так и описано в SPEC §10.1. У Xray и sing-box SOCKS-вход UDP поддерживает.
   UDP через `unbihex-cli` проверен только на уровне outbound (TUN не трогали по §10 карты).
