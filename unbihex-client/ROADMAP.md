# Планы Unbihex (черновик, 23.10.2026)

**Русский** · [English](ROADMAP.en.md)

Unbihex — клиент для ПК, Android и iOS на собственном ядре.


## Этап 0 — сейчас: клиент подключается к реальным подпискам
1. Доделать XTLS Vision + REALITY (готово).
2. Отпечаток TLS (fp=chrome) — готово 27.10: свой ClientHello по шаблону Chrome поверх патченного rustls. ClientHello rustls легко отличить от браузера; ТСПУ в РФ
   умеет блокировать по отпечатку. Варианты: собственная сборка ClientHello, повторяющая Chrome
   (как uTLS), или BoringSSL (крейт `boring`) на месте rustls для внешнего TLS/REALITY.
   Без этого REALITY может работать хуже, чем у Xray-клиентов.
3. Проверка совместимости против настоящего Xray в CI (Xray собирается из Go-модуля):
   матрица «протокол × транспорт × версия Xray». Это же — публичное доказательство совместимости.

## Этап 1 — сильный клиент
4. Правила: geosite.dat / geoip.dat (формат v2fly) и `.srs` (sing-box rule-set),
   компактное сопоставление доменов (trie/succinct-структуры), mmap.
   Сразу улучшит режим «Россия напрямую» (geosite:category-ru, geoip:ru).
5. Горячая перезагрузка: правила, списки доменов и смена сервера без разрыва уже открытых
   соединений. Техника: Router/таблица outbound за `ArcSwap`, у каждого соединения своя ссылка
   на старую версию; новые соединения берут новую.
6. Mux + XUDP: UDP поверх Vision (игры, звонки), меньше рукопожатий.
7. XHTTP (SplitHTTP): режимы packet-up / stream-up / stream-one, HTTP/2 (h2/hyper) и HTTP/3
   (quinn + h3), XMUX, x_padding, вместе с REALITY. Сильный козырь, но после Vision/REALITY:
   в нынешних подписках преобладают именно они.
8. Обход DPI: фрагментация TLS ClientHello, «шумы» UDP (в старом клиенте эти настройки уже были).
9. Подписки в формате Xray JSON и sing-box JSON (многие панели отдают их Happ/v2rayN).

## Постоянно
- Фаззинг разборщиков (cargo-fuzz): ссылки, VLESS/SS-заголовки, DNS, HTTP.
- Бенчмарки против Xray и sing-box: пропускная способность, задержка, память
  (на iOS у Network Extension лимит ~50 МБ — это преимущество Rust, его стоит показывать цифрами).
- Совместимость — движущаяся цель: Xray обновляется часто, нужен регулярный прогон тестов на новых версиях.

## Риски
- Отпечатки TLS и активное зондирование — главная причина блокировок, важнее числа протоколов.

## Технические решения (обсуждение 23.10.2026)
- **Отпечаток TLS:** чистый Rust, без BoringSSL (CMake/NASM ломают сборку под iOS/Android/роутеры).
  Свой модуль сборки ClientHello по шаблону Chrome/Firefox: GREASE, порядок расширений,
  набор шифров, padding. Для полного сходства с Chrome нужен ещё гибридный X25519MLKEM768
  (чистый Rust: крейт `ml-kem`). Для REALITY токен кладётся только в SessionId
  (поле Random остаётся случайным и служит солью HKDF и nonce AES-GCM) — уже сделано без форка rustls,
  двойной сборкой ClientHello. Форк rustls — только если шаблонный ClientHello иначе не собрать.
- **Правила на iOS (лимит ~50 МБ):** geosite.dat/geoip.dat не держать в памяти целиком.
  Один раз конвертировать в собственный компактный бинарный формат (отсортированные домены
  с общими суффиксами / succinct trie, диапазоны IP для LPM), читать через `mmap`.
  Поддержать `.srs` (sing-box). Роутер — за `arc-swap` (`ArcSwap<Router>`), чтение без мьютексов.
- **Vision:** прямой режим только для внутреннего TLS 1.3; для TLS 1.2 паддинг заканчивается
  командой 1. Все варианты — в матрице автотестов против Xray (уже есть тест против Xray 26.3.27).
- **XUDP:** 8-байтный GlobalID — ключевой хэш (blake3) от исходного адреса UDP-сокета с
  процессным случайным ключом, как в Xray; без него на сервере не работает Full Cone NAT
  (игры, Discord, звонки Telegram).
